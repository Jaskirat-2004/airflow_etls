## ⚠️ READ THIS FIRST — CHANGED 2026-08-27 (staging + upsert rollout)

Every COPY below now loads into a **_staging** table, NOT the live table.
Nothing is live until `vodafone_upsert_etl` merges staging -> destination and truncates staging.

WHY: before this change, COPY wrote straight into the live tables, which had no primary key.
Loading the same day twice silently doubled it. That is exactly what happened to the head count
on 2026-08-01 and 2026-08-12, and it fanned out through the APR / FTE / attendance facts —
FTE ended up holding two complete copies of itself.

So: **do not "fix" a COPY by pointing it back at the live table.** If a load looks wrong, the
destination now has a PK and will reject a genuine duplicate loudly instead of doubling.

RENAMED 2026-08-27: `vodafone_head_count` -> `head_count` (matches the youbroadband naming).
The CSV file on the server is still named `vodafone_head_count.csv`.

TWO TABLES ARE DELIBERATELY NOT ON STAGING — they load straight into the live table, because
no valid primary key exists for either (details in `config/upsert_config.py`):
  * custom_pool_report  — one row per call LEG; only the export's "#" counter makes it unique
  * custom_tagging      — no key at any width; even the full row is non-unique

## Step 3 — Merge staging into the live tables

Trigger the Airflow DAG:   vodafone_upsert_etl

It upserts each *_staging into its destination on the destination's primary key, then TRUNCATEs
the staging table. Re-running it after an identical load is a no-op on row counts — it only
bumps `updated_at`. Running the master orchestrator does this for you first, then the facts:

    vodafone_master_orchestrator
        trigger_upsert  -> vodafone_upsert_etl
        trigger_etl     -> vodafone_fact_table_etl
        trigger_attendance -> vodafone_fact_attendance_etl

## ⚠️ lead_master — the blank padding rows

`lead_master.csv` carries ~652,868 rows where every field is empty. They are padding from the
source export hitting Excel's 2^20 row cap (1,048,575 total, ~395,707 real leads).

`lead_master.report_date` is NOT NULL on the destination, so those rows cannot be merged.
`vodafone_upsert_etl` strips them from staging automatically (`prune_null_date` in
`config/upsert_config.py`). Better still, export the CSV without them.
